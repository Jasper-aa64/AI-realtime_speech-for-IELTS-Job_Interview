> 用途：把产品的「功能内容 + 交互逻辑 + 使用说明」一次讲清楚，供商业分析会话或外部老师/投资人快速理解产品。
> 配套文档：战略定位见 [`PROJECT_BUSINESS_ANALYSIS_HANDOFF_2026-06-14.md`](PROJECT_BUSINESS_ANALYSIS_HANDOFF_2026-06-14.md)。

## 1. 一句话定位

面向国内雅思考生的 **「口语/写作 AI 训练工作台」**：内置当季机经题库，提供 AI 模拟考、四维评分报告、语料积累与记忆曲线复习，把「练 → 批改 → 复盘 → 复习」做成一个闭环。

## 2. 产品包含哪些内容（功能模块全景）

导航栏自上而下的真实模块：

| 模块 | 入口（导航） | 做什么 |
|---|---|---|
| 首页 | 首页 | 概览 + 快速进入练习/写作 |
| 模拟考 | 模考 | 完整 P1+P2+P3 串考，最贴近真实考试 |
| 口语 Part 1 | P1 | 话题分组练习（按话题成组出题） |
| 口语 Part 2 | P2 | Cue card 看图卡片陈述题 |
| 口语 Part 3 | P3 | 深度追问，每次抽 3 道少练的题 |
| 口语报告 | 口语报告 | 历史报告列表 + 四维评分详情 |
| 每日写作 | 每日写作 | Task 1 / Task 2 写作 + AI 批改 |
| 写作报告 | 写作报告 | 写作历史报告与分项反馈 |
| 语料库 | 语料库 | P1/P2/P3 题库整理 + 个人语料卡片 |
| Takeaway（口语积累） | Takeaway | 收藏好表达，听英文 + 记忆曲线复习 |
| 写作积累 | 写作积累 | 写作好句/模板的收藏与复习 |
| 拼写错词训练 | 拼写错词训练 | 高频错词 SRS 拼写训练 |
| 账户/设置 | 头像 | 登录、外观、AI 来源、余额钱包 |

### 2.1 题库资产（核心壁垒）

- **口语**：P1（新题 / 保留题 / 归档）、P2 题卡、P3 追问，按 2026 年 5–8 月当季机经整理。
  - 数据来源以 **爱听写 / 神奇题库** 当季全量抓取为权威底库，再用 IELTSBro PDF / 公开季题单补充「薄话题」，做了去重（避免近义重复灌水），过期话题进归档。
  - 当前规模：P1 共 48 话题 / 288 题，每个话题至少 4 题（不再是早期「每题 3 个」的占位）。
- **写作**：Task 1 / Task 2 题库（含配图）、写作模板（Frames）、高频拼写错词表。

### 2.2 AI 批改与报告

- **口语**：四维评分（流利度与连贯、词汇、语法、发音）+ 总分 Band，附中文解释、Band 7 升级表达、AI 教练点评，逐题转写。
- **写作**：分段批改、语法/表达升级、拼写纠错、个性化学习画像。

### 2.3 复习与留存系统

- **Takeaway / 写作积累**：保存表达 → 点击听英文（TTS）→ A/D 记忆曲线复习（A=已掌握、D=明天再复习），导航上有「到期复习」红点提醒。
- **薄弱项 / 重练队列**：根据练习数据用间隔重复算法挑出最该重练的题。

### 2.4 账户与计费

- 注册/登录、个人资料、外观设置。
- **Token 钱包**：AI 调用前预留额度、调用后结算、流水台账、充值、价格快照——把 AI 成本显性化、可控。

## 3. 核心交互逻辑（用户怎么用）

### 3.1 口语练习闭环（最关键的主流程）

```
选择模式(P1/P2/P3/模考)
   → 系统按算法出题（P1 整组出题，P3 抽 3 道少练题）
   → 考官语音播题(TTS)
   → 用户开口录音（实时语音识别 ASR，WebSocket 实时上行）
   → 完成本题 → AI 生成追问(可选) → 继续
   → 全部结束 → 提交评分
   → 生成四维报告 + 中文解释 + Band7 改写 + 教练点评
   → 可把好表达存进 Takeaway 复习
```

- **P1 出题算法**：以「话题」为单位整组出现，每次尽量凑够 8–12 题，优先出练得最少的话题，保证覆盖均匀。
- **P3 出题算法**：从该 P2 题卡的完整追问列表里，按「练习次数少优先」加权随机抽 3 道。

### 3.2 写作练习闭环

```
选题(Task1/Task2) → 写作 → 提交批改(AI)
   → 分段反馈 + 语法/表达升级 + 拼写纠错
   → 进写作报告 → 好句进「写作积累」复习
```

### 3.3 复习闭环（日活/留存抓手）

```
导航看到「到期复习」红点
   → 进 Takeaway / 写作积累 / 拼写训练
   → 点「开始」→ 卡片听英文 / 拼写
   → A=掌握、D=明天再练（拼写训练可按 Enter 继续）
   → 系统按记忆曲线安排下次复习
```

> 注：当前新手对「点开始 → A/D → Enter」这类操作不够直觉，是已知的上手门槛（详见战略文档）。

## 4. 技术架构（给懂技术的分析者）

| 层 | 技术 | 说明 |
|---|---|---|
| 前端 | 原生 JS 单页应用（无框架） | 模块化多文件：`app.js` 主逻辑、`api-client.js`、`view-router.js`、`corpus-takeaway.js`、`spelling-drill.js` 等 |
| Web 服务 | Django 5.2 + Channels，daphne(ASGI) | HTTP API + WebSocket（口语实时语音识别） |
| 后台任务 | 独立 AI Worker 进程 | 消费 `AITask` 队列，跑批改/评分等耗时 AI 任务 |
| AI 路由 | Claude CLI（claude-sonnet）+ OpenAI 兼容(GPT/Codex) | 双通道，可配置主用 + 失败回退；回退会被诚实标注，不伪装成功 |
| 语音 | TTS（考官播题）+ 实时 ASR（PCM 上行） | 录音转写、考官音频 |
| 数据 | SQLite | 题库以 JSON 种子文件随仓库分发（`data/ielts/...`） |
| 部署 | 本地 Windows 进程 + cloudflared 隧道 | 公网预览地址走 trycloudflare，指向本机 8767 端口 |

**主要数据实体**：用户/资料（CustomUser、UserProfile）；AI 任务（AITask）；计费（TokenWallet、WalletReservation、WalletLedgerEntry、PriceSnapshot、PaymentOrder）；口语（SpeakingAttempt、SpeakingTurn、SpeakingReport、SpeakingTrainingObservation、LanguageTakeawayEntry、TakeawayReviewState、ExpressionReplacementEntry）；写作（WritingPrompt、WritingEntry、WritingScore、SpellingDrillWord、WritingLearnerProfile、WritingFrameTemplate）。

## 5. 部署 / 使用说明（运维要点）

### 5.1 启动本地服务栈（Windows）

```powershell
# 一键脚本（daphne + AI worker），需先在项目根目录放好 .env
.\scripts\windows\start-ielts-stack.ps1
```

服务监听 `127.0.0.1:8767`；公网访问由独立的 cloudflared 隧道转发到该端口。

### 5.2 ⚠️ 关键运维须知

- **改了代码或题库后必须重启 daphne 才会生效**。daphne 无自动重载，题库是进程启动时一次性加载进内存的单例；只 `git push` 不重启，线上仍是旧内容。
- 重启会中断当前正在进行的练习，并让公网地址短暂（约 5–10 秒）不可用；端口不变，隧道会自动重连。
- 浏览器侧改了前端需 **硬刷新**（Ctrl+Shift+R）以绕过缓存。

### 5.3 安全/成本约定

- 密钥只走 `.env`（已 gitignore，绝不入库/日志）。
- AI 来源默认不乱切，避免题库整理等操作意外消耗 Claude 额度。

## 6. 给商业分析会话的速读结论

- **已具备**：可信当季题库 + AI 四维口语报告 + AI 写作批改 + 记忆曲线复习 + 成本可控的 Token 钱包，练-批-复盘-复习闭环已经跑通。
- **最大短板**：新手上手门槛（功能多、按钮语义不直觉），以及公网/AI 来源/余额等基础设施概念对普通用户不友好。
- **天然商业切入**：AI 负责高频批改+题库+复习，老师负责内容校准+教程+高价值诊断，做「AI 工具 + 人工点评」的混合服务，而非一上来宣传「替代老师」。
