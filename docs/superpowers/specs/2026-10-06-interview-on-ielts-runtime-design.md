# 模拟面试改用雅思的真实组件 — 设计

日期：2026-10-06 · 分支 `ui-polish` · 取代 `2026-10-05-interview-studio-v2-design.md` 里的「界面」与「场次流程」部分（内容模型、面试官决策规则、百分制保留）。

## 1. 为什么改

v2 只照搬了雅思的结构和样式，交互是另写的 `interview.js`，所以：读题 → 准备 3 秒 → 自动录音的流程没有；识别失败退回打字；报告栏没有三个点菜单和删除；模式开关没有动效；点击整页重绘导致抖动。用户要求：界面和流程照搬雅思，不要自己另做。

## 3. 后端

### 3.1 新的口语模式

`SpeakingAttempt.Mode` 增加四个值：`iv_full`（完整面试）、`iv_project`（项目深挖）、`iv_knowledge`（知识点）、`iv_reverse`（反问环节）。`start_attempt` 允许这四个值，`_build_turns` 交给 `apps.interview` 的出题函数：

- 出题顺序和题源沿用 v2：自我介绍 → 每个项目 → 知识点（简历技术栈 → JD → 精选题补足）→ 奖项 → 反问；分段模式只出对应阶段。
- 每个 `SpeakingTurn`：`part="interview"`，`metadata.prompt` 带 `stage`、`role`（main / follow_up）、`corpus_entry_id`、`language="zh"`；`metadata.timers` 为 `{"prepare": 3, "answer": 上限}`。答题上限：自我介绍 120 秒、项目讲述 180 秒、知识点 120 秒、追问 90 秒、反问 60 秒。
- 第一题读题语音在开场时生成，其余在后台生成（雅思现有逻辑）。

### 3.2 读题语音与识别

- 面试题的读题语音用中文音色（`examiner_tts_services` 按 `prompt.language` 选音色和 `language="zh"`）。
- 录音识别按 `language` 传给火山识别；面试轮次用中文。
- 注意：用户 `.env` 里火山识别的配置目前是注释掉的，打开之前所有回答都会被识别为空（与雅思同样处理）。

### 3.3 追问：接在雅思的追问流上

雅思高强度 P1 的做法是答完一题后前端打开 `follow-up-stream`，服务器插入一条追问轮次并流式写入题目、生成读题语音。面试在 `_follow_up_stream_context` 里增加 `kind="interview"`：

- 调用 v2 的面试官决策（`next` / `follow_up` / `probe`），深度上限照旧：标准模式每题 1 层，追问压力 3 层（项目 4 层），服务器强制。
- 决定 `next`、AI 失败、或回答为空：不插追问，流里发「跳过」事件，前端进入下一题（复用雅思已有的「没有回答，跳过追问」分支）。
- 反问环节：面试官先回答你的问题（这段回答也生成读题语音并播放），再问「还有其他想了解的吗」。

### 3.4 评分与报告

- `score_attempt` 遇到面试模式改用 v2 的百分制评分（五个维度 30/25/20/15/10、能力边界、下一步、逐题点评），结果存进 `SpeakingReport.report_payload`；`overall_band` 等雅思字段留空。
- 每题还要给一份「参考回答」（对应雅思的 7 分参考），存在轮次上，报告表格第三列和编辑弹窗的「AI 参考」都用它。

### 3.5 报告列表

- `/api/history` 增加 `domain` 参数：雅思界面只取雅思模式，面试界面只取面试模式。没有任何回答的中止场次不进入列表（与雅思一致）。
- 删除、三个点菜单、筛选、横向报告栏全部用雅思现成的接口和前端代码。

### 3.6 语料存储

继续用 `InterviewCorpusEntry`（已有来源键、孤儿标记、父子追问），另加三组接口，返回格式与雅思对应接口完全一致，前端换一个接口地址即可：

- 知识点：P1 语料库格式，按方向分组（C++、低延迟与性能、系统与并发……）。
- JD 与反问：P1 语料库格式，两组：岗位题、反问。
- 简历：P2 语料库格式。题卡 = 每个项目一张 + 每个技术方向一张（例如 C++、低延迟、AI native）+ 自我介绍 + 奖项；题卡上的筛选（替代 人物/地点/事件/物品/特殊）为：全部 / 项目 / 技术栈 / 自我介绍 / 奖项；每张题卡的追问 = P3 追问格式，数量不限，可自定义添加。

### 3.7 定制（简历 / JD）

生成结果先作为草稿返回（不写入语料库）；前端展示草稿，用户逐条修改、删除后点「加入语料库」，再写入。重新生成仍然不覆盖用户已经改写过的答法。

### 3.8 旧的面试场次

`InterviewSession` / `InterviewTurn` 及其接口不再使用，前端不再调用；表先保留，确认无用后再删。用户数据库里没有这些数据。

## 4. 前端

- 模式切换器保留。面试模式下侧栏各项直接打开雅思的视图（练习页、报告、语料库、首页、写作页式的定制页），带一个「面试」数据开关：接口地址、模式名、筛选项、少量标签文字（例如阶段名、报告标题）。
- 练习页：用雅思 P1 的练习面板与录音流程本身，不再另写。标准模式 / 追问压力用雅思的开关和动效。
- 报告：用雅思的报告栏和详情渲染；详情在面试模式下把 Band 分数卡换成百分制（总分 + 五个维度），表格列为 问题 / Your recording / 参考回答，辅导行为面试官判断。
- 语料库：知识点、JD 与反问用 P1 语料库界面；简历用 P2 语料库界面和 P3 追问编辑。
- 首页：用雅思首页的渲染代码，换面试的文字、轮播（仍是占位图）和数据。
- `interview.js` 里自写的界面全部删除，只留模式切换和数据开关；它的旧样式随之删除。

## 5. 实施顺序

1. 练习流程 + 报告（读题、准备 3 秒、自动录音、识别失败处理、追问、百分制报告、报告栏菜单与删除）。
2. 三个语料库界面 + 报告里打开的编辑弹窗（带 AI 参考）。
3. 首页 + 定制的草稿确认。
4. 删除旧的面试界面和接口调用。

每一步结束：后端测试、网页测试、在桌面端可见窗口里逐页核对，并和雅思同位页面截图对比。

## 6. 不在本次范围

- 实时语音（原生 C++，阶段 2）。
- 真实 AI 出题 / 评分质量调优。
- 首页轮播图的正式图片。
