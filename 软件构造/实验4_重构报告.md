# 实验4：音频预处理模块重构报告

## 最高原则

本次实验4不是重做 IELTS Web 产品，而是在现有成熟功能之上完成一次可验证的内部重构：

```text
现有浏览器录音 / 上传 / 报告生成 = baseline
C++ audio_core / WASM / realtime gateway = 增量加速层
旧批处理链路 = fallback
```

因此，本实验只重构音频预处理能力的内部结构，不改变 P1/P2/P3、Mock、每日写作、报告页等用户功能设计。

## 重构目标

把旧 C++/Qt 体系里分散在音频采集、实时语音捕获和协议链路中的可复用音频处理逻辑，抽成一个无 IO、无平台依赖、可测试、可编译到 WASM 的纯函数核心：

```text
include/ielts/audio_core.h
src/ielts/audio_core.cpp
src/ielts/audio_core_wasm.cpp
```

这个核心后续同时服务两条路径：

- 浏览器端 `audio_core.wasm`：用于 VAD、静音裁剪、重采样、基础音频质量观察。
- Linux 后端 realtime gateway：作为实时语音网关的音频预处理核。

## 重构前的问题

### 1. 音频处理逻辑和 IO 混在一起

旧 C++ 工程里的相关能力分布在：

- `src/services/audio_manager.cpp`：设备采集、播放、PortAudio IO。
- `src/ielts/realtime_speech_capture.cpp`：语音捕获、VAD 式切分、流程控制。
- `src/common/protocol.cpp` 与 `src/services/realtime_client.cpp`：实时语音协议和 WebSocket 客户端。

这些模块各自有价值，但它们把设备、协议、状态流转和算法逻辑放在相近层级里。结果是：

- 无法直接把算法部分编译成浏览器 WASM。
- 单元测试必须绕过设备或网络依赖。
- 后续接 openspeech realtime gateway 时，很容易把协议和预处理继续耦合。

### 2. 浏览器侧缺少可替换的音频分析核心

前端原有录音链路以浏览器 `MediaRecorder` 和转写结果为主，没有一个独立、可复用的 frame analyzer 抽象。后续如果要接 WASM，只能直接改正式 P1/P2/P3 录音流程，风险过高。

### 3. 开源 VAD 复用缺少隔离层

实验5需要复用一个真实开源功能模块。直接把 WebRTC VAD 调用散落在业务代码中，会让后续替换算法、fallback、WASM wrapper 都变困难。

## 重构后的结构

### 1. 抽出 `audio_core` 纯核

`audio_core` 对外暴露稳定的算法接口：

| 接口 | 作用 |
| --- | --- |
| `NormalizedRms` | 计算归一化 RMS |
| `NormalizedPeak` | 计算归一化 peak |
| `AnalyzeFrame` / `IsSpeechFrame` | 基于 RMS threshold 的 deterministic VAD fallback |
| `AnalyzeFrameWithVad` / `IsSpeechFrameWithVad` | 通过 `VadConfig` 选择 VAD backend |
| `TrimSilence` | 按 frame 裁剪首尾静音 |
| `ResampleLinear` | 轻量线性重采样 |

该层只依赖 C++ 标准库和 `libfvad` C API，不依赖 Qt、PortAudio、WebSocket、Django 或浏览器对象。

### 2. 用 Strategy 隔离 VAD backend

`VadConfig` 让调用方在两条路径之间切换：

- `VadBackend::RmsThreshold`：确定性 fallback，便于测试。
- `VadBackend::WebRtc`：通过 `libfvad` 复用 WebRTC VAD。

这让开源库复用被封装在算法核内，业务层只关心统一的 `FrameAnalysis` 结果。

### 3. 用 Adapter 暴露 WASM 边界

`src/ielts/audio_core_wasm.cpp` 把 C++ `std::vector<int16_t>` 接口适配成 Emscripten 可导出的 C ABI：

- `_audio_core_normalized_rms`
- `_audio_core_normalized_peak`
- `_audio_core_is_speech`
- `_audio_core_is_speech_webrtc`
- `_audio_core_trim_silence`
- `_audio_core_resample_linear`

浏览器 demo 只通过这些 wrapper 调用 WASM，不直接依赖 C++ 内部类型。

### 4. 前端保留 baseline，WASM 作为可选观察层

正式产品录音仍由现有浏览器流程负责。WASM 预处理以 feature flag 形式接入：

```text
?wasm_audio=1      使用 WASM analyzer，失败则 fallback
?wasm_audio=mock   使用 mock-rms analyzer
默认               不初始化 WASM
```

这保证了：

- 生成的 `audio_core_wasm.js/.wasm` 不存在时，正式流程不受影响。
- WASM 加速层失败时，用户仍能完成练习和报告生成。
- 后端只持久化小型 metrics summary，不上传 raw PCM frame。

## 使用的重构手法

| 重构手法 | 落点 | 效果 |
| --- | --- | --- |
| Extract Module | 从旧音频/实时链路中抽出 `audio_core` | 算法核可独立编译、测试、复用 |
| Separate IO from Computation | `audio_core` 不含设备、网络、UI | 同一核心可服务 native 与 WASM |
| Strategy | `VadBackend::RmsThreshold` / `VadBackend::WebRtc` | 开源 VAD 与 fallback 可切换 |
| Adapter | `audio_core_wasm.cpp` | 把 C++ API 适配到浏览器 WASM |
| Feature Flag | `?wasm_audio=...` | 不破坏 baseline，支持渐进验证 |
| Characterization Tests | `audio_core_test` 与 validation scripts | 用测试锁住重构行为 |

## 关键代码证据

| 文件 | 证据 |

| `src/ielts/audio_core.cpp` | RMS、peak、trim、resample、libfvad-backed VAD 实现 |

## 验证方式

实验4验证脚本：

```bash
scripts/run_experiment4_refactor_validation.sh
```

它验证三类内容：

1. `audio_core` 边界仍然纯净，没有重新引入 Qt、PortAudio、WebSocket、curl、Django 等 IO/UI/网络依赖。
2. C++ native test、WASM build、frontend syntax、Django regression 仍通过。
3. 生成的 WASM artifact 仍被 `.gitignore` 忽略，不进入仓库。

## 重构收益

### 可测试性提升

重构前，音频行为和设备/协议耦合，难以稳定复现。重构后，`audio_core_test` 能用固定样本验证 RMS、peak、VAD、静音裁剪和重采样。

### 可复用性提升

同一 C++ 核可以被三处复用：

- native C++ test / 后端 realtime gateway。
- Emscripten WASM browser demo。
- 正式 speaking recording 的 feature-flagged diagnostics。

### 可部署性提升

正式 Web 产品不依赖本地 Mac 音频设备或 Codex CLI。`audio_core` 是跨平台 C++，后续可以在 Linux 云服务器和浏览器中分别编译运行。

### 风险降低

WASM 只是增量观察层。即使 WASM artifact 缺失、加载失败或 analyzer 报错，正式录音、上传、转写和报告生成仍走 baseline。

## 剩余边界

本实验4不实现完整 realtime gateway。后续工作仍包括：

- 把 `protocol.cpp` / `realtime_client.cpp` 重构成常驻 C++ realtime gateway。
- Django ASGI / Channels 接入实时转写。
- 按 openspeech 协议完成连接生命周期、背压、重连和 fallback。

这些属于后续增量任务，不影响本次 `audio_core` 抽核的重构验收。
