# 重构完成度报告

> 阶段性收口报告。目的不是宣布所有重构完成，而是在继续切 `web/static/app.js` 之前，把当前架构重构已经闭环的部分、仍然存在的债务、下一阶段的量化基线固定下来。

## 1. 当前架构定位

项目当前主运行时已经是 **Django 后端 + `web/static` 单页前端 + C++/WASM 音频加速层**。

- Django 是生产业务入口：账号、口语练习、写作、报告、题库、billing、AI task 都走 Django。
- 旧 `web/ielts_server.py` 已退役为历史参考，不应继续扩展。
- C++ 当前已经进入默认音频预处理路径：`audio_core` 经 Emscripten 编译为 WASM，在浏览器录音链路中运行；后端 C++ realtime gateway 仍是后续 backlog。
- 当前主要架构债务集中在两个大文件：`web/static/app.js` 和 `backend_django/apps/speaking/services.py`。

## 5. 剩余技术债排序

1. **继续拆 `web/static/app.js`**
   - 当前 8776 行，仍是最大前端维护风险。
   - 最高性价比下一刀：写作 prompt picker 渲染 / 筛选 / 选择逻辑。
   - 原因：该区域相对独立，且直接影响每日写作和题库弹窗的可维护性。

2. **继续拆 `backend_django/apps/speaking/services.py`**
   - 当前 4139 行，仍包含 attempt/turn runtime、Codex/HTTP follow-up orchestration、report regeneration、TTS refresh 等多类职责。
   - 建议优先拆 runtime orchestration，而不是继续拆零散 helper。

3. **追问延迟从 P50 约 4.66s 调到稳定 1-3s**
   - 这不是当前重构 goal 的阻塞项，HTTP provider 已经把 Codex CLI 冷启动问题解决。
   - 但 4.66s 对真考官追问体感仍偏慢。
   - 后续可从更快模型、供应商端点、首 token 流式展示三个方向调优。

4. **C++ realtime gateway**
   - 现在 C++ 已进入浏览器 WASM 预处理，但常驻 realtime gateway 尚未接入。
   - 这是“边说边出字 / 可打断考官”的核心后续工程，适合作为单独大 goal。

5. **发音评测**
   - 需要先确认上游语音服务是否支持 pronunciation assessment / 音素级评分。
   - 不建议和 realtime gateway 混做。

## 6. 阶段判断

可以确认的结论：

- 旧 server 退役、Django 主运行时、WASM 默认开、HTTP 追问主路径这几条主线已经闭环。
- 项目已经从“旧 server + 大文件堆叠”进入“Django 主体 + 模块化拆分进行中 + C++ 加速层”的阶段。
- 但还不能宣称“生产级架构重构全部完成”，因为 `app.js` 和 `speaking/services.py` 仍然过大。

下一阶段建议：

1. 继续 `app.js` 第三刀：写作 prompt picker。
2. 每拆一刀记录行数变化，保持本报告作为基线。
3. 前端拆到主要 view 逻辑可分块维护后，再回头拆 speaking runtime orchestration。
