# 重构完成度报告

> 阶段性收口报告。目标是说明当前产品架构已经重构到哪里、哪些目标已经闭环、哪些债务仍然存在。本文不定义新功能，只作为后续验收和排期依据。

## 1. 当前定位

当前项目主线已经从旧 `web/ielts_server.py` / C++ 单机体系，迁到 **Django 新后端 + `web/static` 单页前端 + C++/WASM 加速层**。

旧 server 已退役为历史参考；生产业务入口应走 Django。C++ 不再作为独立旧客户端存在，而是作为可复用的音频性能层和未来实时语音网关地基。

## 5. 剩余技术债排序

1. **前端 `web/static/app.js` 模块化**
   - 当前 8883 行，是最大维护风险。
   - 建议下一阶段按 view router、writing、speaking runtime、reports、takeaway/corpus 分块拆出模块。

2. **`speaking/services.py` 继续拆分**
   - 当前 4139 行，仍是最大后端服务债务。
   - 优先拆 runtime attempt/turn orchestration、Codex/HTTP follow-up orchestration、report regeneration、TTS refresh 编排。

3. **业务 WIP 分线收口**
   - 当前考季题库、七彩外观、写作/口语测试改动需要独立 task 和独立提交。
   - 不应混入架构重构提交。

4. **实时语音网关**
   - 已有 C++/WASM 地基，但后端 realtime gateway 尚未启动。
   - 适合作为后续大 goal，而不是当前收口任务的一部分。

5. **发音评测**
   - 仍需确认上游语音服务是否支持音素级或 pronunciation assessment。
   - 当前不宜和 realtime gateway 混做。

## 6. 阶段判断

阶段性结论：**项目已完成从旧 server 到 Django 主运行时的迁移，并完成多条关键重构闭环；但还不能宣称“生产级架构重构全部完成”。**

当前合理状态是：

- 生产业务入口：Django 可作为主运行时。
- 旧 server：已退役、可冻结保留。
- C++：已进入默认音频预处理路径，后续可扩展到 realtime gateway。
- 架构债务：主要集中在 `web/static/app.js` 和 `backend_django/apps/speaking/services.py`。

下一阶段建议先做 **前端模块化**，因为它影响 UI 性能、可维护性和后续功能迭代速度；后端 speaking 继续拆分可作为并行但较低优先级的长期任务。
