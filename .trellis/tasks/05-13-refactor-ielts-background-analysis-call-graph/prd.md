# Refactor IELTS Background Analysis Call Graph

## Goal

Reduce Codex calls in the IELTS web analyzing/report flow by moving per-turn Band 7 answer generation and per-turn coaching into one background call per completed turn, then using a single final scoring/review call when the attempt is scored.

## What I Already Know

- The user wants target Codex calls to be `answered turn count + 1 final call`.
- Per-turn Band 7 spoken versions are useful; the current overall Band 7 concept for P1/P3 should stop being generated by Codex.
- Recent concise Markdown coaching and `overall_review` behavior must be preserved.
- Recent TTS audio Range/cache and frontend preloading must be preserved.
- The worktree is dirty; unrelated changes must not be reverted.
- Backend and frontend specs require deterministic fallbacks when Codex/CLI is unavailable.

## Requirements

- After each turn completes, start background generation for that turn without delaying the next question response.
- The per-turn generation must use one Codex call that returns both `band7_version` and `ai_coaching`.
- If the per-turn Codex call fails, returns invalid JSON, or misses required fields, fill deterministic fallback values.
- `/api/attempts/{id}/score` must reuse per-turn generated values where present and avoid separate per-turn Band 7 and coaching Codex calls.
- Final scoring should use one Codex call and include overall review/comments when feasible; otherwise keep deterministic overall review without adding a second Codex call.
- Stop generating overall attempt-level Band 7/model audio for P1/P3 reports via Codex. Legacy compatibility fields may remain deterministic or empty.
- Frontend report rendering should continue showing per-turn Band 7 and coaching, with pending/fallback states handled defensively if needed.

## Acceptance Criteria

- [x] Completing a turn schedules a background per-turn Band 7/coaching generation job and returns promptly.
- [x] Scoring a fully background-generated attempt performs only the final scoring Codex call.
- [x] Missing per-turn generation at score time does not multiply Codex calls; deterministic fallback content is used.
- [x] P1/P3 score payloads no longer include Codex-generated overall Band 7/model audio.
- [x] Existing report payload shape remains compatible for history rendering.
- [x] Tests cover reduced call count by mocking `run_codex` where practical.

## Definition of Done

- Tests added or updated for backend call graph and report payload shape.
- `python3 -m py_compile web/ielts_server.py tests/test_ielts_web_server.py` passes.
- Relevant unittest target passes.
- `node --check web/static/app.js` passes if frontend code changes.

## Out of Scope

- A durable production queue or worker system.
- Changing external Codex CLI billing behavior outside this call graph.
- Redesigning the report UI beyond necessary compatibility handling.

## Technical Notes

- Likely backend touchpoints: `score_with_codex`, `model_answer_with_codex`, `build_band7_version`, `enrich_turn_feedback`, `ai_coaching_with_codex`, `score_attempt`.
- The app runs on `ThreadingHTTPServer`, so a minimal `threading.Thread` based background mechanism is acceptable for this local app.
- Preserve thread safety around shared `attempts` state and report saves as much as the current architecture allows.
