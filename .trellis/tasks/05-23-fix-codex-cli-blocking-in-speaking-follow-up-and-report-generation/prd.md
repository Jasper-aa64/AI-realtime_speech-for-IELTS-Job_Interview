# Fix Codex CLI Blocking in Speaking Follow-up and Report Generation

## Problem

P1 work/study follow-up and final speaking report generation are not reliably usable after the Django runtime migration.

Observed behavior:
- P1 after recording stays on `Generating follow-up...` for a long time and may never advance.
- Final speaking report generation cannot reliably complete.
- Codex CLI itself can return valid output, but the Django migration now blocks user-facing HTTP requests on too many synchronous Codex calls.

## Key Discovery

Old server behavior was not simply "Codex CLI is unusable". Old flow was lighter:
- Turn complete saved the answer and moved forward.
- Final report primarily called `score_with_codex` once, then assembled the report.

Current Django flow regressed by chaining multiple Codex calls in one user action:
- P1 complete waits synchronously for Codex follow-up.
- Score generation calls Codex for batch turn feedback, scoring, and overall review serially.
- Any slow Codex call blocks the entire user-visible request.

## Requirements

1. Codex CLI remains the normal AI backend for P1 follow-up and final report scoring.
2. Do not silently make hardcoded fallback the normal path.
3. P1 complete must not stay stuck as if saving is still in progress.
4. Final report generation must not depend on multiple serial Codex calls before a report can be written.
5. Fallback is allowed only when Codex genuinely fails, and metadata must clearly mark fallback.
6. TTS and nonessential enhancement calls must not block response creation.
7. Tests must prove Codex is called on the normal path and fallback metadata is explicit on failure.

## Preferred Approach

- Keep P1 follow-up generated by Codex when possible, but structure the UI/API so the user sees a correct `Generating AI follow-up...` state and receives a generated turn when done; do not call it "Saving".
- For final report, restore a lighter old-server-like critical path:
  - score with Codex first and persist the report from that result;
  - use scorer-provided `overall_review` where possible;
  - do not require separate batch turn-feedback and separate overall-review Codex calls before report persistence.
- Optional turn-level Band 7/coaching can be Codex-backed only if it does not prevent report creation; otherwise mark pending/fallback honestly.

## Validation

- Targeted speaking tests for P1 follow-up and report generation.
- `python3 backend_django/manage.py test apps.speaking.tests`
- `python3 backend_django/manage.py check`
- `node --check web/static/app.js`
